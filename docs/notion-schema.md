## DB 1. 루키즈 마스터

인턴 인원 관리의 단일 진실 공급원(Single Source of Truth).

| 프로퍼티 | 타입 | 설명 | 예시 |
|---|---|---|---|
| 이름 | Title | 인턴 성명 | 김루키 |
| 전형 | Select | 소속 전형 | `서울영커리언스` / `표준현장실습` / `직접채용` |
| 상태 | Select | 현재 상태 | `실습중` / `수료` / `중도포기` |
| 실습 기간 | Date (range) | 시작일 ~ 종료일 | 2026.03.09 → 2026.08.31 |
| 소속 대학 | Text | 학교명 | OO대학교 |
| 학과 | Text | 전공 | 컴퓨터공학과 |
| 연락처 | Phone | 비상 연락 | 010-XXXX-XXXX |
| 산재보험 | Checkbox | 가입 여부 | [x] |
| 협약서 | Checkbox | 제출 여부 | [x] |
| 서류 체크리스트 | Multi-select | 전형별 필수 서류 현황 | `산재보험`, `협약서`, `신원조회`, `서약서` |
| 미제출 서류 | Formula | 체크리스트 중 미완료 항목 수 | `0` = 완료 |
| 평가 총점 | Rollup | 출결/평가 로그 DB에서 합산 | 85.5 |
| 성과 태스크 | Relation | → 성과 엔진 DB | (연결) |
| 출결 로그 | Relation | → 출결/평가 로그 DB | (연결) |

## DB 2. 성과 엔진

운영계획서 직무 ↔ 실제 태스크 ↔ 프로덕션 기여를 잇는 핵심 DB.

| 프로퍼티 | 타입 | 설명 | 예시 |
|---|---|---|---|
| 태스크명 | Title | 수행한 작업 | API 엔드포인트 개발 |
| 담당자 | Relation | → 루키즈 마스터 | 김루키 |
| 주차 | Select | 운영계획서 기준 주차 | `1주차` ~ `24주차` |
| 직무 계획 | Select | 운영계획서 [붙임1] 직무 항목 | `프론트엔드 개발` / `API 설계` / `QA` 등 |
| 매핑 상태 | Select | 계획 대비 실행 여부 | `매칭완료` / `미매칭` / `계획외추가` |
| 결과물 링크 | URL | PR, 디자인 파일, 문서 등 | https://github.com/... |
| 프로덕션 반영 | Select | 실제 제품 반영 여부 | `반영완료` / `진행중` / `미반영` |
| 반영 위치 | Text | 제품 내 반영 지점 | 관리자 대시보드 > 통계 페이지 |
| 기여도 코멘트 | Text | 관리자가 작성하는 기여 설명 | "차트 컴포넌트 신규 개발, 성능 40% 개선" |
| 관리자 승인 | Checkbox | Approve 로그 | [x] |
| 승인일 | Date | 승인 시점 | 2026.04.15 |
| 데일리 로그 | Text | 해당 태스크 관련 일일 기록 | "API 스펙 정의 완료, 내일 구현 착수" |

## DB 3. 출결/평가 로그

출퇴근 + 평가 관찰 기록을 하나의 타임라인으로 관리.

### 3-A. 출결 영역

| 프로퍼티 | 타입 | 설명 | 예시 |
|---|---|---|---|
| 날짜 | Title (or Date) | 기록 일자 | 2026.03.10 |
| 담당자 | Relation | → 루키즈 마스터 | 김루키 |
| 출근 시간 | Text | 실제 출근 | 09:00 |
| 퇴근 시간 | Text | 실제 퇴근 | 18:00 |
| 실습 시간 | Formula | 퇴근 - 출근 - 점심 | 8.0 |
| 시간 초과 여부 | Formula | 실습 시간 > 8 이면 경고 | `정상` / `초과` |
| 출결 상태 | Select | 당일 상태 | `출석` / `지각` / `조퇴` / `결석` / `휴가` |

### 3-B. 평가 관찰 영역 (2주 단위)

| 프로퍼티 | 타입 | 설명 | 점수 범위 |
|---|---|---|---|
| 평가 주기 | Select | 관찰 시점 | `1-2주차` / `3-4주차` / ... |
| 1. 실무 지식 | Number | 전공 관련 실무 이해도 | 1~5 |
| 2. 업무 수행력 | Number | 주어진 업무 완수 능력 | 1~5 |
| 3. 문제 해결력 | Number | 이슈 대응 및 해결 | 1~5 |
| 4. 의사소통 | Number | 보고, 질문, 피드백 | 1~5 |
| 5. 협업 능력 | Number | 팀원과의 협력 | 1~5 |
| 6. 책임감 | Number | 마감 준수, 자기 관리 | 1~5 |
| 7. 적극성 | Number | 자발적 참여 | 1~5 |
| 8. 성장 가능성 | Number | 학습 속도, 개선 의지 | 1~5 |
| 9. 근태 | Number | 출결 성실도 | 1~5 |
| 10. 조직 적응 | Number | 문화 적응, 예절 | 1~5 |
| 11. 종합 의견 | Text | 관찰 코멘트 (비공개) | "주도적으로 코드리뷰 참여" |
| 평가 합계 | Formula | 항목 1~10 합산 | 42 / 50 |

## Relation 구조 (DB 간 연결)

```
루키즈 마스터 ──┬── 1:N ──→ 성과 엔진 (한 인턴이 여러 태스크)
               └── 1:N ──→ 출결/평가 로그 (한 인턴의 날짜별 기록)
```

---

## 자동화 연동 포인트 (코드로 처리할 부분)

| 자동화 | 읽는 DB | 하는 일 |
|---|---|---|
| 서류 마감 알림 | 루키즈 마스터 | 미제출 서류 있으면 알림 발송 |
| 시간 초과 감지 | 출결/평가 로그 | `시간 초과 여부 = 초과`인 행 감지 → 알림 |
| 직무 미매칭 경고 | 성과 엔진 | `매핑 상태 = 미매칭`인 주차 경고 |
| 보고서 생성 | 전체 DB | 기간별 데이터 취합 → 제출용 문서 생성 |

### 변경 사항 (초안 → 실제)

| 구분 | 초안 | 실제 구현 | 이유 |
|---|---|---|---|
| 명칭 | 루키즈 마스터 등 | `CG Rookies` 접두 통일 | 기존 DB 명명 컨벤션 일치 |
| 기수/전형 | 마스터 내 Select | 기존 `CG Rookies 관리 문서`에 **relation** | 기수=사업 레이어가 이미 존재, 단일 진실 공급원 유지 |
| 퇴사 처리 | (명시 없음) | **행 삭제 금지**, `상태`로만 관리(수료/중도포기) | 75% 성과금 증빙 위해 퇴사자 기록 영구 보존 |
| 현재 인원 | 고정 관리 | `상태=실습중` **필터 뷰**로 자동 집계 | 인원 교체 잦음 → 동적 집계 |
| 출결/평가 | 분리 서술 | 1개 DB + `구분(출결/평가)` Select | 한 타임라인 관리 |

### 생성된 DB / 데이터소스 ID

부모: **관리페이지(👮‍♀️)** `3141847f-058f-81c9-a45d-dacf2add91fc`

| DB | data_source_id |
|---|---|
| CG Rookies 마스터 | `cc04c75b-98d8-4fe5-8a9c-f26ea6501996` |
| CG Rookies 성과 엔진 | `bfa48e08-3bf6-47e7-b92e-ed1106d003a9` |
| CG Rookies 출결·평가 | `4df8e0eb-4e11-4994-afb4-7de0512074d3` |
| (기존) CG Rookies 관리 문서 = 기수·사업 | `3301847f-058f-8003-bca0-000bd495bd59` |

### 실제 Relation / Rollup 구조

```
CG Rookies 관리 문서(기수·사업, 기존)
        │ 1:N  (마스터의 "기수·사업" ↔ 관리문서의 "소속 인턴")
        ▼
CG Rookies 마스터
   ├─ "성과 태스크"   ─1:N─→ 성과 엔진("담당자")
   ├─ "출결·평가 로그" ─1:N─→ 출결·평가("담당자")
   ├─ Rollup "평가 총점"   = sum(출결·평가.평가 합계)
   └─ Rollup "누적 태스크" = count(성과 태스크)
```

- 출결·평가 `평가 합계` = 10개 평가항목(실무지식~조직적응) Formula 합산
- 뷰: 마스터에 `현재 실습중` 필터 뷰(상태=실습중, 기수순 정렬) 생성됨
